# TeamPilot 使用说明书

## 1. 登录与角色

打开前端地址后使用账号密码登录。默认本地开发账号：

- 管理员：`admin / admin123`
- 演示成员：`zhangsan / 123456`、`lisi / 123456`、`wangwu / 123456`

系统按角色和权限控制按钮显示。管理员可以在系统设置中调整角色权限。

## 2. 项目管理

项目管理页是日常使用主入口。

- 顶部汇总区展示项目数、进行中项目、任务总数、已完成任务和完成率。
- 从任务记录提交真实进度、进展说明和本次投入工时。
- “巡检报告”用于查看日报或周报，支持刷新和邮件发送。
- 点击“新建项目”填写项目资料，再按需要创建和组织任务树。

项目行可展开任务树。项目状态由任务自动推导：

- `规划中`：没有任务，或任务都还没到开始时间。
- `进行中`：存在已开始且未完成的任务。
- `已完成`：所有未删除任务都已会签完成。
- `已归档`：管理员手动归档。

## 3. 任务管理

任务支持父子层级、多人负责人、工时、开始日期、截止日期、进度和会签。

- 点击任务名称打开任务详情抽屉，可编辑任务名称、目标和描述。
- 点击“查看记录”打开进展抽屉，可手动提交真实进展。
- 负责人支持多选，列表中会完整显示所有负责人。
- 有子任务的任务可以折叠，子任务支持同级拖拽排序。
- 删除任务为软删除，子任务会同步进入删除状态；恢复父任务后才能恢复子任务。

任务状态只保留三种：

- `待开始`：开始日期晚于当前时间。
- `进行中`：已到开始日期且未完成。
- `已完成`：进度达到 100% 后，由有权限角色会签确认。

## 4. 进展更新

在项目任务树或任务看板中打开任务的进展记录，填写当前进度、真实进展说明和本次投入工时后提交。提交后可以在历史记录中追踪填写人、时间和进展内容。

有子任务的父任务按子任务权重汇总进度。任务进度达到 100% 后，仍需有权限的人员会签确认，才会显示为已完成。

配置了内部平台数据源的任务，也可以执行任务数据 Skill，并在检查结果后点击“采纳进展”。数据采集本身不会自动修改任务进度。

## 5. 巡检报告与周报

项目管理页的“巡检报告”支持两种报告：

- 日报：每天 07:00 自动生成一次，输出风险项目、持续阻塞、本期交付成果、需要支持的事项、优先推进和待验收任务。
- 周报：每周五 12:30 按系统规则生成一次，项目进展情况表覆盖所有未归档项目。
- 切换：在日报和周报之间切换时，只读取已有缓存。
- 刷新：在弹窗中点击“刷新”，才会按当前选择的日报或周报重新生成并覆盖缓存。

日报和周报由确定性规则生成，以会签交付事实和需支持的任务为依据，不再根据个人累计进度或填报次数评定快慢。未解除的结构化阻塞会持续出现；每次刷新会保留一个独立报告版本，可在团队协作的“历史报告”中查看。

周报会额外包含“项目进展情况表”：项目、总进度、本周进展、任务完成、逾期任务、风险等级和下周建议。

报告可以通过邮件发送。部署前需要配置 SMTP：

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=robot@example.com
SMTP_PASSWORD=your-password
SMTP_FROM_EMAIL=teampilot@example.com
SMTP_USE_TLS=true
SMTP_USE_SSL=false
REPORT_DEFAULT_RECIPIENTS=pm@example.com,lead@example.com
REPORT_TIMEZONE=Asia/Shanghai
```

如果页面里填写了接收人，优先使用页面输入；否则使用 `REPORT_DEFAULT_RECIPIENTS`。

## 6. 仪表盘

仪表盘用于管理视角查看整体情况。

- 概览：总任务数、进行中、已逾期、完成率。
- 我的任务：按紧急/重要四象限展示当前登录人的未完成任务。
- 项目进度概览：展示项目完成度和风险标签。
- 团队工作负荷：按任务负责人统计未完成工作量。

团队工作负荷优先使用任务 `estimated_hours`。如果任务没有预估工时，系统按层级折算：

- 一级任务：8 小时
- 二级任务：4 小时
- 更深层子任务：2 小时

## 7. 人员管理

人员管理页可以查看成员列表、角色、部门、个人介绍、技能和工作量信息，便于了解成员背景并手动安排任务。

## 8. 系统设置

系统设置包含：

- 权限管理：配置角色可用功能。
- 技能标签：维护人员技能库。
- 模型配置：管理模型供应商、协议、API 地址、密钥和模型列表。

在“模型配置”中选择供应商预设或自定义供应商，再配置协议与 API 地址。支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages；对应的鉴权请求头由协议自动处理，也可添加供应商要求的额外请求头。

点击“获取可用模型”读取供应商的模型列表；不提供模型列表接口的网关可手动填写模型 ID，并选择默认模型。“测试模型”会使用当前表单向选定模型发送一条简短推理请求，可能产生少量供应商费用。获取模型成功与推理成功分别显示，测试不会自动保存表单。

编辑时 API Key 留空保留已有密钥，勾选“清除已保存密钥”后保存可移除密钥；已保存的自定义请求头也不显示原值，可留空保留或删除该行后保存以移除。配置失败会保留输入，修正后可以重试。模型管理权限为 `system.model_manage`，已有角色的旧设置管理权限自动兼容。

## 9. 任务数据 Skill

任务数据 Skill 用于把内部平台数据接入任务进展。

流程：

1. 在任务详情里描述数据来源，例如“这个任务的数据从测试平台获取。接口是 GET /api/test/feature/{feature_id}/summary。”
2. 系统生成 Skill 草稿。
3. 用户测试执行并确认。
4. 后续可执行 Skill 获取外部数据。
5. 用户确认采纳后才写入任务进展历史。

采集草稿由确定性规则生成，需人工测试和确认；只能访问已配置的连接器。

## 10. 推荐日常流程

1. 新建项目，创建任务并组织任务树。
2. 给任务分配负责人、工时和截止日期。
3. 提交真实进度，或检查并采纳任务数据 Skill 的执行结果。
4. 查看巡检报告，处理风险、逾期和待会签项。
5. 查看周五自动生成的周报，必要时手动刷新后邮件发送。

## 11. 团队协作工作台

从侧栏进入“团队协作”，或从项目、任务详情跳转。先选择项目和计划周：

1. **责任与交付**：为任务指定一名主责、协作者、验收人和验收标准，说明责任变更原因。新主责登录后确认接受交接，再提交成果链接或可核验说明。指定验收人可以通过或退回，退回必须说明原因。通过仍要求任务进度达到 100%，且没有未解除阻塞。历史任务会标为“待明确主责”，不会自动把多人中的任意一人认定为主责。
2. **阻塞处理**：明确问题、原因、处理人、下一步和期限。未解除问题跨日保留，超期会标记并显示项目负责人作为升级对象；解除时填写结果。处理状态与任务三种主状态分别展示。
3. **本周容量**：填写成员本周可用工时，再按每人、每个末级任务分配工时。系统显示超容量缺口；未填容量时显示待确认，不默认认为有 40 小时。父任务与子任务不重复计入。分配范围是当前用户有权查看的项目。
4. **交付计划**：维护关键里程碑及对应任务，建立任务前后依赖。自依赖和循环依赖会被拒绝。冻结计划基线后可对照原截止日期、工时与负责人，查看变化；改期、工时和人员调整留下前后值、操作者与原因。
5. **承诺与复盘**：记录本周承诺的成果，补充实际结果与偏差说明。过去周的承诺目标不可事后改写；交付结果按该周结束前的验收事件判断，后续重开不会改写历史结果。复盘中的改进行动直接生成有负责人、期限、验收标准和来源的任务；创建人负责验收，主责仍须确认接手。

项目可以设为“公司内可见”或“仅项目授权成员”。私有项目仅项目成员、负责人及管理员可见；观察者只读。设为私有前，先把承担未完成责任的人员加入项目。移除成员、降为观察者或停用账号前需完成未结束责任的交接；项目负责人可在工作台移交项目负责权。报告历史、人员任务统计与实时通知同样遵循项目访问范围。

“历史报告”保留刷新前的版本；邮件发送使用服务器上当前可访问的报告版本。权限被撤销后，原有私有项目的缓存与历史版本不会继续开放。
